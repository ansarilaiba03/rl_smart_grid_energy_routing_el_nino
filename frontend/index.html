Methodology

The website is now an inference interface, not a dataset browser.

Live input

The user enters 105 demands (15 cities × 7 categories) and one total available-energy value. No date is required.

Trained model

The backend loads the saved PPO policy and its VecNormalize statistics. The browser never contains the model weights.

Allocation

The PPO action controls the same allocation mechanism used during training: priority-weighted water filling, with the learned battery and priority controls applied by the backend.

Priorities

  • Hospitals: 10
  • Public water works: 9
  • Educational institutions: 6
  • Residential: 5
  • Commercial: 3
  • Industry: 2
  • Agriculture: 1

Research testing

The 2026 held-out dataset should still be used for your paper's model evaluation. A manual website scenario is live inference, not a replacement for the held-out test set.

Important assumption

Because this one-shot interface does not ask for battery SOC, time, temperature or recent shortage history, the backend uses fixed El Niño/reference context for those observation fields. That makes this a real-time scenario adapter, not a claim that the model observed a real grid state.
